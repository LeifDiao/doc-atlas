Why doc-atlas凭什么用它

Read the panel, not the pile.看面板,不必再翻那一摞。

A "summarize this PDF" tool gives you more text to read. doc-atlas does the opposite: it consolidates across files, surfaces where they disagree, distills the result into a scannable visual panel — and keeps every number one click from the page it came from.「帮我总结这个 PDF」给你的是更多要读的字。doc-atlas 反过来:跨文件合并、把矛盾的地方挑出来、把结果炼成一张能扫读的可视化面板——而且每个数字点一下就能回到它出自的那一页。

A1
Any format → one layer任意格式 → 统一中间层

PDF / Word / PPT / Excel / HTML / EPUB / Markdown all normalize to a Markdown layer (via markitdown). PDF tables keep their numeric columns; scanned PDFs fall back to OCR. Page numbers and images survive for traceability.PDF / Word / PPT / Excel / HTML / EPUB / Markdown 全部归一化成 Markdown 中间层(用 markitdown)。PDF 表格保住数值列;扫描版走 OCR 回退。页码和图片都留着,方便溯源。

A2
Merge, don't list是合并,不是罗列

Multiple files are de-duplicated and woven into one unified outline — not summarized one by one. When numbers, dates, or conclusions disagree, the conflict is shown explicitly instead of silently picking one.多个文件去重后织成一张统一目录——不是逐文件摘要。当数字 / 日期 / 结论打架,冲突会被显式列出,而不是悄悄替你选一个。

A3
The logic diagram is the star逻辑图是主角

The core causality / relationships become a prominent, full-width diagram you can click to zoom — not a footnote. Plus data charts (Chart.js) wherever the numbers deserve a picture.核心因果 / 关系做成醒目的整行大图,点击可放大——不是塞在角落的脚注。数字该上图的地方,再配数据图表(Chart.js)。

B1
Distilled + traceable炼化 + 可溯

Every claim carries a source badge back to file + page. A distillation report shows coverage, compression ratio, and what's still to verify — and an adversarial fact-check refutes high-risk claims against the source before rendering.每条结论都挂着回到「文件 + 页码」的来源角标。炼化体检表给出覆盖率、压缩比、待核实占比;渲染前还有一道对抗式核查,拿高风险结论回原件证伪。

B2
Structured render, offline结构化渲染,离线可开

The AI only writes a structured model.json; a deterministic renderer compiles it to one dashboard.html. Stable, self-checkable, token-light. Images are inlined as base64 — double-click, no server.AI 只产出结构化 model.json,确定性渲染器把它编译成单个 dashboard.html。稳定、可无头自检、省 token。图片 base64 内嵌——双击即开,不用服务器。

B3
Paper skin, your language纸本皮肤,跟你的语言

A warm rice-paper, blue-ink, magazine-style layout that's a pleasure to read. It asks which language you want the panel in before scanning, then keeps the whole dashboard — content and UI — in it.暖米纸 + 蓝墨 + 杂志式版面,读起来舒服。扫描前先问你要哪种语言的面板,然后整张面板——内容和界面——都用它。

How it works它怎么跑

The AI writes structure. The renderer draws.AI 写结构,渲染器作图。

01
Scan扫描
Pick the panel language, scan the folder, and confirm which documents to include.选面板语言,扫描文件夹,跟你确认纳入哪些文档。
02
Normalize归一化
Each file becomes a Markdown layer — page numbers and images preserved.每个文件转成 Markdown 中间层——页码和图片都留着。
03
Consolidate & check合并 + 核查
Merge across files, surface conflicts, then an adversarial fact-check against the source.跨文件合并、挑出冲突,再对抗式回原件核查。
04
Render渲染
model.json → one self-checked dashboard.html that opens offline.model.json → 一个经自检、离线可开的 dashboard.html。
scan → normalize (any format → Markdown) → consolidate (dedupe · conflicts) → fact-check → model.json → deterministic render → self-check → dashboard.html 扫描 → 归一化(任意格式 → Markdown) → 合并(去重 · 冲突) → 事实核查 → model.json → 确定性渲染 → 自检 → dashboard.html

On first use it installs the parsing dependencies (markitdown + PyMuPDF, ~290 MB) into an isolated .venv — only after you consent. Decline and nothing is installed.首次使用会把解析依赖(markitdown + PyMuPDF,约 290MB)装进隔离的 .venv——征得你同意才装。不同意则不装任何东西。
